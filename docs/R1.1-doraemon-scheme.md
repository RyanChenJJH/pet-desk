# R2 阶段：机器猫（哆啦A梦）高级交互与秘密道具方案

> **适用角色**：机器猫（Doraemon / 哆啦A梦）  
> **对接运行时**：Clawd-on-Desk (`theme.json` Schema v1 高级特性)  
> **前置依赖**：R1 阶段分层母版与 6 大基础状态已锁定  
> **交付阶段**：R2（高级交互、自由漫步、秘密道具与完整生命周期）

---

## 1. 方案定位与升级目标

R1 阶段解决了“桌宠从无到有”的 MVP 基础循环与光标跟随。R2 阶段的核心目标是：**赋予机器猫真正的灵魂与深度互动感**。

### 1.1 R2 四大升级维度
1. **真实物理行走（Free Roam Walking）**：由 `roam.svg` 提供真正迈步、双臂前后摆动、红尾巴微摆的圆润步伐，彻底替代默认的机械上下平移。
2. **多维交互反馈（Reactions Rig）**：支持桌面悬空拖拽、鼠标左戳/右戳脸颊、双击从四次元口袋掏出经典秘密道具（竹蜻蜓/任意门）。
3. **随机待机彩蛋（Idle Animations）**：闲置时随机触发“偷偷咬一口铜锣烧”或“手忙脚乱在四次元口袋里掏出奇怪道具”。
4. **完整生命周期衔接链（Full Sleep Sequence & Agent Events）**：打哈欠（yawning）→ 打瞌睡（dozing）→ 倒头大睡（collapsing）→ 揉眼醒来（waking），以及上下文压缩扫地（sweeping）、子任务多开杂耍（juggling）等高级事件。

## 3. 漫步运动学与自由漫步（Roam）规范

依据 `clawd-on-desk` 规范：
- `roam.svg` 必须**画风朝右**（Facing Right）。Clawd 漫步向左走时会自动在 X 轴镜像翻转。
- 迈步循环周期建议设定为 `0.8s`，配合脚底基准线 `Y = 17.5`，步幅控制在 `4px`，确保没有在地面“滑冰”的违和感。

```xml
<!-- 漫步关键腿部与手臂摆动关键帧 -->
<style>
  @keyframes legWalkLeft {
    0%, 100% { transform: translateX(0) translateY(0); }
    25% { transform: translateX(2.5px) translateY(-1.5px); }
    50% { transform: translateX(4px) translateY(0); }
    75% { transform: translateX(1.5px) translateY(0); }
  }
  @keyframes legWalkRight {
    0%, 100% { transform: translateX(4px) translateY(0); }
    25% { transform: translateX(1.5px) translateY(0); }
    50% { transform: translateX(0) translateY(0); }
    75% { transform: translateX(2.5px) translateY(-1.5px); }
  }
  @keyframes armSwingLeft {
    0%, 100% { transform: rotate(-15deg); }
    50% { transform: rotate(15deg); }
  }
  @keyframes armSwingRight {
    0%, 100% { transform: rotate(15deg); }
    50% { transform: rotate(-15deg); }
  }
</style>
```

## 4. 四次元秘密道具库（Gadget Library）

在 R2 阶段建立独立的零件库 `work_space/doraemon/01_master/gadgets-library.svg`，统一供各动画按需提取：

1. **竹蜻蜓（Take-copter）**：
   - 细黄色杆轴（`#FFD166`）+ 顶端旋转双叶螺旋桨（转动时带有浅黄色半透明动态残影圆面）。

   - 上下两片微鼓的金黄烘焙煎饼皮，中间露出深红褐色红豆馅沙。

   - 方形吐司切片，表面印有加减乘除与微积分算式符号。
4. **缩小灯（Small Light）**：
   - 复古绿色手电筒，前镜头发散出锥形半透明金光。
5. **时间包袱皮（Time Furoshiki）**：
   - 粉色底色、表面布满深红色倒转时钟时针图案的可爱包裹。

## 6. 验证与分级交付策略

R2 包含的状态较多，实施时将划分为 3 个递进 Task Group：
1. **Group A（交互核心）**：`roam.svg` + `reactions` 4 个交互状态。
2. **Group B（道具彩蛋）**：道具母库 + `idleAnimations` 2 个随机彩蛋。
3. **Group C（生命周期与事件）**：完整睡眠 4 状态链 + 4 个 Agent 特殊状态。
每个 Group 交付后，立即调用 `validate-theme.js` 实施回归检查，保证主题时刻处于可玩可用状态。
