# 女孩 R4.0 设计与技术方案

> **原始需求与背景回溯**：
> - 提出时间：2026-09-15
> - 业务场景：用户先提出“请利用项目下的开源项目pet-forge，采用**APNG 路线**  创建R4_GIRL下的动画素材。动画采用R4_GIRL下的图片中的角色。先执行R4.0方案和计划。然后再按照方案和计划执行。”随后改为“我改成SVG的路线，看下如何将文件下的那张`GIRL.png` 图片，做成动画”，并对“参考图语义重绘 SVG 母版 + CSS 状态动画”的建议回复“同意”。
> - 已拍板技术决策：采用全 SVG 路线；以 `work_space/R4_GIRL/GIRL.png` 为唯一角色参考图；不走 APNG；不把 PNG 自动描摹结果直接当作动画母版；以分层语义 SVG 母版作为唯一真实源；首版交付 Clawd-on-Desk 可加载的 6 个核心状态。
> - 对接运行时：Clawd-on-Desk (`theme.json` Schema v1)
> - 交付目标：`work_space/R4_GIRL/`

## 1. 输入图像判断

`GIRL.png` 是一张近景绘画插图，角色特征明确：橘棕色双丸子头、白色花饰、困倦闭眼表情、厚眉、橘色腮红/雀斑、前景 V 手势、橘色衣服。

该图不适合直接 `png2svg` 后做动画，根因是：

- 背景不透明，自动描摹会把背景色块一起矢量化。
- 绘画笔触复杂，直接描摹会得到大量匿名路径，缺少可驱动的“眼睛、头发、手、花饰”等语义层。
- 原图是近景半身构图，不能凭空补全腿部来做传统走路动画。

因此 R4.0 采用“忠实提取角色特征 + 简化重绘语义分层”的 SVG 路线。

## 2. 造型策略

R4.0 不追求像素级复刻，而追求桌宠运行时可识别、可动画、可维护：

- 保留：双丸子头、白花、闭眼困倦感、橘色大腮红、雀斑、V 手势、暖橘衣服。
- 简化：笔触纹理、背景渐变、复杂皮肤阴影。
- 禁止：凭空扩展全身、额外武器/宠物/复杂道具、脱离原图的新发型或新服装。

## 3. SVG 技术路线

统一使用 `viewBox="-25 -25 50 50"`，角色主体控制在固定尺寸基线内，脚底/投影接近 `baselineY = 18`。

分层母版位于：

- `work_space/R4_GIRL/01_master/girl-master.svg`

母版层级：

- `#shadow-js`：桌面投影。
- `#body-js`：运行时身体倾斜挂点。
- `hair-back`：后发与双丸子。
- `face`：脸部与肤色主体。
- `eyes-js`：眼部跟随挂点，保持闭眼风格，仅轻微偏移。
- `cheeks`：腮红与雀斑。
- `hand`：前景 V 手势。
- `flowers`：白色花饰。

## 4. 状态拆解

首版交付 6 个核心状态：

- `idle-follow.svg`：轻呼吸、发梢/花饰微摆、困倦闭眼轻微跟随。
- `working.svg`：身体轻点头、眉毛轻抖、手势微动，表示专注工作。
- `thinking.svg`：头部慢倾斜、眉毛一高一低、问号气泡出现。
- `notification.svg`：花饰和腮红弹跳，惊喜感提示。
- `sleeping.svg`：头部下沉慢呼吸，添加 `Z` 气泡。
- `roam.svg`：面朝右的轻飘移动/侧向摆动，不补全腿部。

## 5. 运行时约束

- SVG 内严禁 `<script>`。
- 严禁外部资源、外部字体、外部样式表。
- 动画全部使用内联 `<style>` 与 CSS `@keyframes`。
- 循环动画 `0%` 与 `100%` 保持闭环。
- `idle-follow.svg` 必须保留 `#eyes-js`、`#body-js`、`#shadow-js`。
- `theme/theme.json` 必须为无 BOM UTF-8。
- `visibleHeightRatio` 使用 `0.42`，`baselineBottomRatio` 使用 `0.05`。
